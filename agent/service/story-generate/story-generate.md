# story-generate

## v1

- 模块职责：**把一句心愿变成一篇成稿的完整生成过程**。story 模块负责入口与历史管理，本模块只负责「生成中」这段旅程；生成完成后把剧本 id 交回 story。
- 入口：从 story 页的语音圆钮 / 文本输入 / 灵感条目进入，路由 `/story/generate?seed=<心愿文本>`。带着 `seed` 进来就**自动开始生成**，不让用户再点一次；没有 `seed`（语音入口）则先落到心愿输入态，写完再发。
- 路由注册在 `StatefulShellRoute` **外面**：生成过程要独占屏幕，底部行动条（停止 / 继续 / 读全文）和 tab 栏会抢位置。
- 页面形态是**竖向时间线**，不是传统气泡聊天：一次生成是一条有先后顺序的旅程（提问 → 反问 → 大纲 → 正文），用时间线比左右气泡更能表达"进度"。
- 时间线条目共 5 种：
  -- **心愿**：用户那句话，置顶第一条。
  -- **澄清卡**：AI 的反问。单选 / 多选 / 混合 / 纯文本四种形态；允许自定义时在选项下方附文本框。提交后卡片收起为一条"已回答"摘要，不可再改。
  -- **大纲卡**：标题 + 一句话梗概 + 分幕节拍 + 结局。底部两个动作：「确认大纲」直接开写；「修改大纲」需先填意见，空意见时按钮禁用。确认/修改后卡片同样收起。
  -- **正文**：流式逐字出现，末尾带光标；生成完成后光标消失。
  -- **失败**：内联重试卡，**不清空已生成的内容**。
- 状态与反馈：
  -- 等待首字这段窗口必须有明确进行态（思考指示器 + 阶段文案），否则用户会重复触发。
  -- 生成中底部主行动变成「停止生成」；停止是本地断流，不算失败。
  -- 全程**禁止重复提交**：待用户作答时不能再发心愿，生成中不能再点生成。
- 四态：加载（首帧未到 → 思考指示器）· 空（无 seed → 心愿输入引导）· 错误（内联重试卡 + 保留残篇）· 有数据（时间线）。
- 生成完成后：底部出现「读全文」与「再写一篇」两个动作，并把标题露出到页头。
- 特殊错误：当天已有未完成的会话（后端 `DAILY_GENERATION_IN_PROGRESS`）时，重试卡的动作换成「继续上次创作」，点了走 `retry` 恢复。
- 返回拦截：生成中直接返回会丢掉这次生成，需二次确认。

## v2

- 时间线每条都带**时间戳**（`HH:mm`，跟随 locale 格式化），位置统一在条目头部右端：心愿 / 澄清 / 大纲 / 正文四类共用同一条头部（图标 + 归属标签 + 时间），时间只有落在固定位置才扫得动。时间取**条目诞生时刻**，正文流式追加时不刷新——显示的是"这段几点开始写的"。
- 澄清卡头部改为「AI 想确认一下 + 时间」独占一行，问题文本另起一行占满宽度（问题常有两三行，与图标同行时右侧时间会被顶到问题中段）。
- 等待态文案从一句固定文案改为**按阶段轮播**：
  -- 三个文案池按当前所处步骤取（理解心愿 / 搭大纲 / 写正文），由时间线最后一条推断；文案与实际进度对不上就是假进度，用户下次不再信它。
  -- 每 4 秒换一句，带淡入 + 上移转场；换句子这个动作本身就是"还活着"的证据。
  -- 等待超过 5 秒后，在文案下方显示**已等待秒数**，把"不知道要多久"变成有量感的等待。秒数用等宽数字，不左右抖。
- 后端 `status` 事件的 `stage` 取值定下来后，改为优先按 stage 选词，本地推断退化为兜底（代码里已留 TODO）。

## v3

- 添加语音识别的库完成语音识别的输入的功能
  -- 走**端侧识别**（iOS Speech 框架 / Android SpeechRecognizer），不经后端：免费、无网络往返、有实时中间结果。封装成 `SpeechRecognizer` 门面，业务层不直接碰插件（和 `DioClient` 之于 `Dio` 同理）。
  -- 生成页空态的心愿输入用**点按**式（点一下开始、再点一下结束），不是按住：这一页是"补一句话"的场景，让用户一直按着屏幕说话既累又挡视线。故事页那颗大圆钮仍是按住（见 `story.md` v5）。
  -- 识别结果**实时写进输入框**，说完能改再提交；中途出错/取消退回说话前的内容。
  -- 三种失败各有各的出路，不可合并：没权限→引导去系统设置；设备不支持→劝手动写；识别为空→「没听清，再说一次」。
  -- 识别语言跟随界面语言，设备没装对应语言包时回落到系统默认。
