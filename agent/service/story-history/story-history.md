# story-history

## v1

- 模块职责：**已生成故事的库**。story 模块负责创作入口、story-generate 负责生成过程，写完之后这些成稿归本模块管——列表、翻阅、收藏、删除。
- 从 story 模块接管：原 `lib/features/story/screens/history/` 那个 mock 版历史页下线，路由 `/story/history` 改指本模块；story 首页的「最近几条」也改读本模块的真实数据（与全量页**共用同一个控制器**，点进去秒开、两处收藏/删除结果一致）。全应用只保留**一份**历史数据源。
- 首页只露最近 **3** 条（原 mock 版是 5 条）：那一屏的主角是创作入口，5 张卡会把输入区挤出第一屏。首页卡片同样能点星标收藏。
- 入口有两个：① story 首页「查看全部」；② **生成页右上角的图标**——刚写完一篇的那一刻正是最想回头看看写过什么的时候，让人退回首页再找一次是多余的一步。生成中也不禁用该入口：翻历史不打断生成，返回时那一页还在原处。
- 生成成功（`novel_done`）时作废历史缓存：服务端此刻已落库新剧本，不作废的话用户顺手点进历史会看到一份**没有自己刚写那篇**的列表，像是没保存上。
- 列表形态是竖向卡片流：标题 + 摘要（两行）+ 时间 + 收藏星标。摘要按 `story-history.api.md` 的拼装规则算（`plotJson.fullContent` 优先，缺失时四段式拼接后取前 90 字）。
- **分页无限滚动**：滚到底自动加载下一页，不放「加载更多」按钮。加载中在列表底部给一行进行态；加载失败给一行可点重试，**已加载的内容不清空**。
- 下拉刷新回到第一页。刷新时**不**把列表塌成骨架，已有内容留在原地。
- **删除是二次确认，不是撤销**：服务端 `DELETE` 不可逆，做一个"撤销"按钮等于骗人。左滑露出删除，确认后乐观移除并请求；失败则把那条放回原位并报错。
- **收藏就地切换**：点星标立刻变（乐观更新）+ 轻触感，失败回滚并提示。收藏态来自另一次 `/favorite/page` 探测（列表响应没有 `isFavorited`，见接口文档的契约缺口）。
- 四态齐全：加载=骨架屏（满一屏卡片形状）· 空=引导回去创作 · 错误=内联重试卡 · 有数据=列表。
- 点开一条应进**阅读页**；阅读页尚未开工，先给「即将上线」轻提示（代码里留 TODO）。

## v2

- **story 首页右上角加入口**：图标 + 「历史」二字，与页头大标题同排。原来只有列表区那个「查看全部」，位置在第一屏之外，用户得先滚下去才知道有历史；标题行这个入口是任何时候都在的常驻出口。两个入口去同一页，不算重复——一个是"顺着看下来"，一个是"我现在就要去"。
- **卡片重设计，把接口给的信息尽量用上**。一张卡分三层：
  -- 顶部：标题（缺标题时用心愿顶上）+ 收藏星标；
  -- 中部：摘要两行；
  -- 底部：**元信息行** —— 篇幅徽标（短篇 / 中篇 / 长篇）· 文风（后端下发的字符串，原样显示）· 相对时间（今天 / 昨天 / N 天前，超过一周退回日期）。
  -- 心愿（`theme`）与标题不同且标题非空时，在摘要上方补一行「> 心愿原文」——它比标题更能唤起"这篇当初想写什么"。
  -- 元信息缺失就不占位（早期数据常缺 `style`），不显示"未知"。
- **分类筛选**：全部 / 短篇 / 中篇 / 长篇 / 收藏，横向 chip 组，吸在列表顶部。
  -- 前四个走 `/epicScript/page` 的 `length` 参数（`短篇=short`、`中篇=medium`、`长篇=long`），**由服务端过滤**，不在客户端筛已加载的那几页——否则"当前页恰好没有短篇"会被误读成"没有短篇"。
  -- 收藏走 `/epicScript/favorite/page`。
  -- **每个分类各自维护自己的分页与滚动**，切回来不重新加载、不回到顶部。
  -- 在任一分类里收藏 / 删除，其它分类的缓存一并作废（下次进去是新的），否则会出现"收藏了但收藏页里没有"。
- **每个分类的空态各说各话**：全部为空 = 一篇都还没写；某个篇幅为空 = 这个篇幅还没写过；收藏为空 = 还没收藏过。都配一个**跳去故事页开写**的按钮（`goNamed(story)`，不是 `pop`——从收藏空态退回去多半不是用户想要的下一步）。
- **点卡片进爽文详情页**（路由 `/story/history/detail?id=xxx`）：
  -- 头部标题 + 元信息（篇幅 / 文风 / 创建时间）+ 收藏星标；
  -- 心愿原文单独成块；
  -- 正文按 Markdown 渲染，长阅读排版（行高放宽、关掉背景视差）；
  -- 正文**优先用列表已经拿到的全文**，进页秒开；缺全文时才调 `/epicScript/detail` 补，此期间给骨架。
  -- 底部常驻一个「继续编辑」主行动。
- **继续编辑**：先用剧本的 `conversationId` 拉一次会话消息列表，成功后再跳生成页（把 `conversationId` 带过去）。按钮在这段等待里是忙碌态。
  -- 先拉再跳，是为了不把用户丢到一个空白的生成页去等；同一份数据在生成页复用，跳过去不再转第二次圈。
  -- 剧本没有 `conversationId`（早期数据）时，这个按钮直接禁用并说明原因，不能点了没反应。
  -- 会话回放本身是**生成页的能力**，需求写在 `story-generate.md` v4；本模块只负责拿到 id 跳过去。
