# auth

## v1

- 登录页（`/login`）顶部用**分段控件**切换两种登录方式，两种方式共用同一个表单与同一个提交按钮：
  - **邮箱 + 密码**
  - **手机号 + 短信验证码**
- 切换登录方式时**不清空**另一种方式已填的内容；只收起键盘、清掉上一种方式的错误提示。
- 邮箱方式：
  - 邮箱框、密码框（带明文切换）、"忘记密码"入口（页面未就绪时给轻提示）。
  - 登录时密码**只校验非空**，不校验强度——密码规则由服务端说了算，客户端多拦一道会把老账号挡在门外。
  - 页脚有"还没有账号？注册"，点进注册页时把已填的邮箱带过去预填。
- 手机号方式：
  - 只支持日本国内手机号（`070/080/090` + 8 位）。粘贴 `+81 90-1234-5678` 这类写法要能自动归一化。
  - 发码成功后手机号**折叠成打码摘要**（`090****5678`）+ "修改"入口，焦点交给验证码格子。
  - 验证码 6 格 OTP，填满即自动提交。
  - 重发冷却 60 秒，**点击那一刻同步起算**（不等接口回来），发送失败立刻解除冷却。
  - 页脚说明"首次使用的号码将自动创建账号"，**不显示注册入口**（这条路上不存在"还没注册"这个状态）。
- 用户协议勾选：未勾选时**不禁用提交按钮**，让用户点、然后就地报错并抖一下 + 触感提醒。
- 提交成功后先在原页播 400ms 的成功确认（OTP 变对勾），再落地会话触发路由跳转。
- 失败处理按"谁错了"分：
  - 密码错 → 只清密码、保留邮箱、聚焦回密码框；
  - 验证码错 / 过期 → 清空 OTP、聚焦回第一格；
  - 账号被停用 → 错误**钉在邮箱字段下方**（不是 toast，toast 三秒就没了）；
  - 网络 / 服务端故障 → **保留全部输入**，只弹 toast。
- 注册页（`/register`）：
  - 只收显示名、邮箱、密码、确认密码，外加**选填**手机号。体重 / 身高 / 紧急联系人 / 护照拼写属于"下第一单之前"的资料，不在注册收集。
  - 密码带**强度条**（四格 + 一句评价）与规则说明；确认密码边输边校验。
  - 手机号选填，下方给理由（天气改期会发短信，户外看不到邮件），不给强制。
  - 邮箱 / 手机号已被占用的错误**就地钉在对应字段下方**并聚焦过去。
  - 注册成功直接进 app（后端返回的就是可用会话），不要求再登录一次。
- 账号页的"退出登录"是破坏性操作：二次确认对话框 + 中等强度触感，确认后按钮进忙碌态。
- mock 期间登录页底部显示一条**演示账号提示条**（虚线感、弱化色，一眼看得出是脚手架），支持一键填入；接真接口时连同 `data/mock/` 一起删。
